# 内置图像工作流：Images 2.5

## 模型与工具边界

- 本技能面向 GPT-6 Astra 执行设计统筹；技能文本本身不能切换主模型。
- 默认使用当前内置 image_gen 生成与编辑，不自行调用外部平台、API 或旧版 CLI。
- 目标图像系列是 Images 2.5。按当前真实工具声明调用；若没有 model 参数，不添加参数或声称已强制指定后端版本。提示词中的模型名不构成模型选择。
- 有明确模型选择能力时才设置经过核实的目标；工具不可用时说明具体缺口，不静默切换旧模型或外部服务。
- 质量、分辨率、蒙版等 API 能力不自动等于内置工具参数。不要保证原生 4K、中文零错误、像素绝对不变或无限参考图。
- 用户请求写提示词、优化技能或只看目录时，不产生实际图片。

## 参考组织

每次调用明确：编辑底图、产品身份、风格母版、相邻屏边界、需要替换的内容。只携带与本次任务有关的参考。
本地图片在编辑前先用 view_image 查看。所有目标都有本地路径时使用 referenced_image_paths；否则按工具允许的最近图片机制，以最小覆盖数量引用。二者不混用，遵循当前工具上限。无法覆盖全部必要图片时才请用户补传。
不能仅在提示词中写一个本地路径、旧版编号或文件名，就认为工具已看到参考图。

## 生成、复用与编辑

- 全新构图：给出传播目标、实际产品参考、画面层级、必要文字和品牌规则，让模型完成整屏视觉。
- 参考延展：携带确认母版与本屏内容，解释继承哪些规则、允许变化哪些构图。
- 直接复用：在允许范围内排版原资产；不将重新生图当成原图复用。常规拼接与排版可用确定性工具，涉及图像内容修改使用内置图像编辑，除非用户指定其他方法。
- 局部编辑：明确“改什么、哪里改、哪些保留”，以最新确认底图操作。每轮集中解决一类相关问题；用户同时提出多项局部修改时可一起表达，前提是检查范围可控。
- 正式整屏可由内置工具生成，不强制概念通过后再重生一次终稿。交付标准取决于实际检查。
- 精确文字、Logo、包装与证据用真实资产作依据；编辑失败时不可因为工具承诺保留就视为成功。用户允许确定性排版合成时可采用该方式，不暗中绕过“内置修图”要求。

## 输出与失败处理

查看实际返回图像，核对文字、产品和修改范围。无法清楚核对的内容标明缺口，不自称全部通过。
一次失败先诊断参考缺失、提示冲突还是结构错误。连续两轮同类失败且无改善时，停止重复同一办法，改用更清晰参考或更小范围编辑；仍无可行路径时说明具体问题与所需素材。
不无限重试，不用整套重绘掩盖小问题。工具报错按真实错误处理，不能伪报生成完成。
生成图按环境规定展示；当前支持 generatedImage 时原样返回。仅为展示／保存单张生成图，不额外下载上传。长图、分屏打包等明确交付需要时才收集实际输出文件，并按环境文件保存规则处理。
